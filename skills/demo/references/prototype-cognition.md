# 玩法原型认知框架

## 条目定义

- **结论**：通用的是“理解目的→确认流程与规则→表达交互→实现可玩行为→验证与同步”的制作流程，具体系统与产物深度随任务变化。独立玩法不等于独立合成线，活动类型也不等于大型活动。
- **适用范围**：功能片段、主玩法附属活动、主盘变体、独立合成线、地图探索、轻游戏和多系统活动的设计、修改与 Demo 制作。
- **反例/限制**：不能把所有需求扩成完整活动，不能以“小原型”为由省略关键操作和失败恢复；生产后端、运营排期和效果验证需要真实项目数据与另行范围。
- **状态**：已确认的制作约定；下文分类是工作判断方法，不是产品效果定律。
- **依据**：2026-09-17 明确要求未来 Demo 不限定独立合成线或大型玩法，并保留相近的整体制作流程。
- **影响**：先判目的、架构、机制和规模，再选模块与交付层；Merge 经济、合成盘、清图、扭蛋均为条件化知识。
- **更新时间**：2026-09-17。

## 1. 四个维度分开判断

| 维度 | 需要回答 | 决定什么 |
| --- | --- | --- |
| 本次目的 | 理解/Q&A、对齐方案、写文档、出UE、做Demo，还是修一个问题？ | 当前工作范围与是否需要下一阶段 |
| 系统归属 | 在既有主玩法上映射、改变既有规则，还是新增独立操作和状态？资源谁拥有？ | 接口、资源和存档边界 |
| 实际机制 | 玩家反复做的动作是什么？合成、清障、选择、拼图、收集或其他？ | 真正需要实现的规则与反馈 |
| 规模与风险 | 一个控件、一条循环，还是多个系统互相供给？是否涉及随机、不可逆状态或复杂恢复？ | 规格深度、页面数量与验证强度 |

先按实际行为归类，再借用已有类型知识。出现扭蛋机不代表存在独立合成盘；有独立地图不代表必须做大型活动；主线行为映射也可能有复杂结算。

## 2. 不变流程与可选交付

1. **理解**：读取最新材料，复述目标、核心操作、输入输出和结束条件；只追问会改变方向的缺口。
2. **对齐**：确定主流程、手动/自动边界、进度口径和必要节奏。已确认的规则不重新发明。
3. **规格**：写清实际操作的触发、条件、处理、反馈、结果与恢复。规格可以是简短项目记录，也可以是完整策划。
4. **表达**：用适量的 UE 或直接在 Demo 中表达状态与反馈，参考图帮助确定结构，不承担未确认规则的决定权。
5. **实现**：最小范围内做通真实行为，结果与表现分离；外部系统按已确认接口模拟。
6. **验收与同步**：检查核心操作、相关失败分支和真实交付入口，将行为与文档/UE对齐。

这是逻辑依赖顺序，不要求每步都生成独立文件或暂停确认。只在明确要求确认或缺失关键决定时等待；已有产物可复用，已有授权继续执行。

## 3. 按规模选择工作深度

| 范围 | 最小规格 | 交付与验证 |
| --- | --- | --- |
| 一个按钮、面板或动效修改 | 控件状态、触发、输入/输出、关闭和恢复 | 修改现有文件，核对相关过程与前后状态；无需重建整份策划和Figma |
| 单循环小玩法或轻量活动 | 进入→操作→反馈→结果→继续/结束，关键资源或局内状态 | 可玩的核心循环、必要界面、失败/重复/重进边界 |
| 多关卡或多系统活动 | 主流程、模块依赖、资源流、阶段进度、生命周期 | 模块化规则、状态覆盖、跨系统回归；在授权范围内同步策划和UE |

复杂度由相互影响的状态与风险判断，不根据活动名、天数、页面数量或美术题材直接下结论。轻量范围同样需要精确与可用，精美程度不以系统堆叠衡量。

## 4. 机制决定模块，不从模板倒推玩法

- 只有存在合成盘，才展开格子、棋子链、生成器、满盘与合成规则。
- 只有存在地图探索，才展开路径、可达性、揭雾、视角或分区；缩放和镜头引导是否需要由当前需求决定。
- 只有存在随机或序列产出，才定义奖励池/序列、推进、保底和恢复；随机池与预排序列不是同一机制。
- 只有存在持久收集，才展开拥有记录、分类进度和收藏奖励；只展示资源结果不自动产生图鉴。
- 只有依附主产品的活动，才分析主玩法输入与奖励回流；独立轻游戏可以用自己的进入、胜负和重试闭环。
- 只有真实存在到期、跨日、分层或付费，才补这些边界。不用模板空标题暗示项目拥有这些系统。

## 5. 类比知识的使用

先取可复用方法，再对照机制，最后才考虑参数。每条知识保留适用范围、反例、状态、依据与日期；观测样本和试算不提升为当前项目事实。

示例：

- “订单完成后加活动进度”优先验证外部事件重复处理与奖励达成，不自动创建活动合成盘。
- “拼图单关Demo”优先验证输入、合法移动、完成、失败/重试与恢复，不自动加入13天排期、分层、图鉴或主线订单。
- “调整一个收集提示”优先验证新增计数、显示顺序、重复与中断，不强制重新生成脑图、完整Word或大型地图。
- “独立合成线”才启用盘面容量、生成、链路和防卡死；可以很小，也可以很深。

## 6. 复盘沉淀

稳定的方法写入本认知框架；类型特有经验写入类型知识；产品已确认参数留在项目记录。效果类结论需有产品、人群、指标、时间窗和对照证据。更新时替换冲突的默认规则，不把一次修正不断叠加成所有玩法的强制功能。
