# 策划表达与编号 UE 规范

本规范沉淀自对文档层次、交互反馈和交付范围的改稿要求。适用于正式策划与 Demo 上游规格；不规定具体活动玩法、角色、周期、地图数、资源值或入口位置。

## 1. 先还原目的、流程与节奏

- 先读当前指定文件、实际工作表、最新 UE 和已确认规则。说明理解到的主循环、节点、资源口径和缺口，不能未核对就声称“彻底看懂”。
- 区分产品功能总览、竞品观测、数值估值、剧情框架、交互草图与正式决定。参考图上的演示分母、示例价格或旧版本设定不能覆盖已经确认的规则。
- 优先厘清“进入→核心操作→阶段完成→奖励→下一阶段/返回→结束”，以及资源供给、消耗、返还和分层。流程与节奏是文档的骨架，UE 用来表达它们。
- 会改变主循环或手动/自动边界的缺口应尽早提问；仅数值尚未定值时可保留配置空位。已经确认或已经授权推进的事项不重复索要确认。
- 长任务在当前项目保存简短决策记录：最新来源与版本、已确认规则、被替代规则、待定配置、阶段授权和验收状态。恢复上下文时先读记录再核对实际文件。

## 2. 正文写给程序与下游部门

- 以项目策划的口吻直接写产品规则；游戏中的操作者称“玩家”。正式正文不写“用户要求”“根据你发的图”“我建议你”“本轮对话”等对话过程，也不夹带工具执行记录。
- 角色、功能、资源和奖励名称使用当前活动确认的名称；建立术语对应关系，避免同一个对象多种叫法。
- “简单易懂”指关系清楚，不是删掉必要条件或压缩到口号。读者应能直接判断何时发生、怎么操作、看见什么、最终变成什么。
- 需要研发处理的边界用可验收的结果表达，例如“重复点击只扣一次”“结果已保存则不重新抽取”。除非要求实现设计，不用程序术语代替行为说明。
- 未定值集中标在对应配置位置；确定的操作流程仍写全，不用一整段“待确认”替代功能逻辑。

## 3. 先分类，再列步骤

- 每个模块先按含义分组，如“显示与入口”“正常操作”“完成结果”“中断与恢复”。标题取决于实际功能，不要求每个模块凑齐一套空标题。
- 有先后依赖的动作使用有序列表；并列规则、条件分支和例外使用无序列表。不要把所有内容换成同一级圆点后就视为已经分层。
- 表格的描述单元格同样使用小标题、步骤和并列条件，不塞连续长段落；一条表达一个可判断的规则。
- 同类模块保持同一标题顺序与颗粒度；一处写完整规则，其他位置简短引用，不在 UE 表、正文与边界章重复三份完整解释。
- Word 使用真正的标题样式和原生列表。列表起点、续号、缩进与层级必须渲染检查，不能用手打编号掩盖格式错误。

## 4. 写全交互过程，而不只写按钮用途

对实际存在的操作，按时间关系说明：

1. **触发前**：从哪里进入，什么条件下出现，当前显示什么、是否可点。
2. **发起操作**：点击/拖动/自动触发什么，先检查哪些条件，是否扣资源。
3. **结果确定**：资源、进度、对象或领取记录如何改变；失败是否保持原状态。
4. **表现过程**：哪个位置出现图标、气泡、进度条、动画或镜头变化；顺序是什么，期间能否重复操作或中断。
5. **结束状态**：停在哪个界面或目标，哪些元素消失、保留、变灰或变为可领取。
6. **必要边界**：只覆盖当前机制涉及的不足、不可达、重复提交、关闭、重进、断线、到期等分支；写清恢复位置与已确认结果。

“播放动画”“刷新界面”“提示成功”不足以定义反馈。应指出反馈对象、位置、显示内容及结束条件；未确认的时长保持可配置，不自行定死。

## 5. UE 图与逻辑一一对应

- 有 UE 时优先使用“功能模块 / 描述 / 图示”三列，图中编号与描述中的控件编号对应；现有模板单列编号也可沿用。无图的纯逻辑用分组列表或状态对照，不留空图示列。
- 按一个界面或一组相关状态组织图文；同一控件的可用、禁用、进行中、成功、失败状态放在一起。关闭要说明返回哪里、保留什么，不只写“点击关闭”。
- 图片必须来自本次实际核对的界面或明确的设计稿，不能用旧截图配新逻辑。标号放在对应控件旁，不遮挡费用、进度和关键文字。
- 同一动作有明显先后表现时，使用有序步骤，必要时配开始/过程/结果图；静态终态图不能代替过程说明。
- 截图等待面板完成入场，过程图明确捕捉目标状态；不要将半透明过渡帧作为最终 UE 图。
- 正文要说明进度分母及其统计对象。单件收集、任务行、阶段进度、全收集与大奖条件不能因为图上都叫“进度”而混用。

## 6. 交付范围

- 新建或整体重写时，默认聚焦活动流程、界面逻辑、底层功能规则及边界，沿所选模板写至功能开关；不自动填充 AB 测、埋点、独立数值分析、多语言清单、付费分析及其后的规划章节。
- 功能实际依赖的价格、费用、次数、恢复、概率与奖励规则仍在对应模块说明，未定值标为配置项；省略独立数值章不等于省略运行条件。
- 明确要求完整模板或扩展某章时才启用相关后置章节。局部修改不擅自删除既有章节；明确要求“从某章起不要”时删除该范围，并同步清理目录、交叉引用和失效链接。
- 检查与决策记录留在项目工作文件，正式正文不追加制作过程、验收流水账或与产品规则无关的内容。

## 写法示例

以下只示范层次，不规定项目必须采用该收集方式：

**收集成功**
1. 收集确认成功后，记录该物品已拥有并更新所属任务进度。
2. 在手册入口上方显示物品气泡；上方任务提示显示该任务的当前数量和目标数量。
3. 反馈结束后收起临时提示，保留已获得状态。

**重复与中断**
- 重复点击已收集对象不增加数量、不再次弹出“新增”提示。
- 表现中断但结果已确认时，重新进入恢复已获得状态，不再次发奖。

## 阅读验收

- 只看任一模块，能否判断正常操作及主要失败分支的起点与终点？
- 只看表格描述，能否对应到图中具体控件和显示状态？
- 同一条流程里是否混入了互不相关的规则？是否存在一长串无分类圆点？
- 图文中的名称、分母、费用与手动/自动边界是否一致？
- 表头和对应内容是否同页起排，图示是否可读，编号是否连续？
