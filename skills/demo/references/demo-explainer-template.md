# 《Demo 体验说明》通俗模板

## 使用原则

- 为每个可交付 Demo 同步生成一份 `Demo体验说明.md`，放在 Demo 根目录。
- 面向没参与设计的人写，优先使用日常语言；必须用专业词时，当句解释。
- 控制在约 1～3 页 Markdown；先讲怎么玩，再讲规则和限制。
- 不复制完整策划需求，只解释体验者真正需要知道的内容。
- 将尚未实现、只做视觉展示和暂用假数据的部分直接说明。
- 明确 Debug 在模拟什么上游事件；不要把“模拟完成主线订单”写成活动内免费赠送。

## 模板

```markdown
# 《[活动名称] Demo 体验说明》

## 这个活动是做什么的

用 2～4 句话说明：玩家为什么进入、做什么、最后获得什么。避免使用“核心闭环、资源回流、状态机”等词；若必须使用，紧跟白话解释。

## 30 秒上手

1. 通过【真实来源】获得【具体棋子/资源】；若来源属于主玩法，说明用哪个 Debug 按钮模拟该事件。
2. 把两个相同等级的【棋子】拖到一起，合成更高一级。
3. 达到【目标】后会出现【升级/奖励/解锁】反馈。
4. 想重新体验时点击【DEBUG·一键重置】。

## 屏幕上各区域的作用

| 区域 | 你会看到什么 | 可以怎么操作 |
| --- | --- | --- |
| 顶部 | 活动时间、资源、帮助入口 | 查看信息或打开说明 |
| 核心场景 | 本轮目标和主要按钮 | 执行活动的主要操作 |
| 进度区 | 合成链、等级或奖励进度 | 横向查看或观察当前进度 |
| 棋盘 | 活动棋子 | 拖动、点击、移动与合成 |

## 你会看到的反馈

- 新棋子：从来源位置飞入棋盘，并在落点轻微弹跳。
- 合成成功：两个棋子收拢，结果棋子放大回弹，并出现短暂光圈或粒子。
- 达成目标：出现约 2～3 秒的小提示板，自动淡出，不要求反复点击确认。
- 操作失败：屏幕下方显示一句短提示，不清空玩家当前操作。

## 这个 Demo 已经能验证什么

- `[列出真实可操作的循环]`
- `[列出已实现的资源与进度变化]`
- `[列出已实现的边界情况]`

## 暂时没有做什么

- `[例如：正式美术、后端存档、真实付费、完整数值]`
- `[说明这些缺失会不会影响本轮验证]`

## 建议体验路线

`[操作A] → [操作B] → [合成/升级] → [打开图鉴或INFO] → [触发资源不足/满盘] → [重置]`

## 少量术语解释

- **棋子链**：同一种物品从低级到高级的成长顺序。
- **生成器**：点击后消耗资源并产出棋子的入口。
- **待领取区**：棋盘放不下时，临时存放物品的地方。
- **Debug**：为了方便测试而准备的快捷按钮，正式游戏通常不会展示。
```

## 写作检查

- 删除“赋能、抓手、链路、心智、沉淀、范式、闭环”等不必要术语。
- 把“触发反馈表现”改为“出现一个提示”；把“资源回流”改为“奖励会回到主线继续使用”。
- 每段只回答一个问题；操作名称与 Demo 按钮文案完全一致。
- 不解释代码结构，不把内部需求 ID 放进面向体验者的正文。
