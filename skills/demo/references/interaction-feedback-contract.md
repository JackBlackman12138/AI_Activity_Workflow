# 交互过程与反馈验收

适用于已有需求涉及地图探索、奖励预览、任务收集或连续表现的 Demo。以下是实现与检查方法，不要求所有活动新增这些功能；确切方向、上限、数量、价格、层数和动画时长来自当前规格。

## 1. 先把反馈拆成可执行契约

对本轮改动记录：触发条件 → 校验 → 确认的状态变化 → 可见表现顺序 → 结束后的操作 → 失败/中断恢复。区分规则与表现：

- **规则**：扣除、获得、拥有记录、进度和领取状态。由同一个规则源确认，保存后再展示成功。
- **表现**：视角、飞行、气泡、进度动画与红点。只展示已确认结果，不在动画结束回调里重新随机、计数或发奖。
- **输入**：定义哪些动作处理期间锁定，哪些可取消演示；视觉取消不等于撤回已经保存的结果。
- **规格同步**：代码、编号 UE、文档和体验说明必须使用同一名称、统计分母、前置条件与手动/自动边界。

## 2. 地图类活动（仅适用时）

### 视角与缩放

- 地图世界坐标与 HUD 屏幕坐标分开。若需求包含缩放，支持目标设备上的实际手势，明确中心锚点、上下限、重置、边缘夹取和比例是否保存。
- 缩放和平移不改经济或任务进度；拖动松手不误触底下障碍，双指操作不被当成两次点击。
- 角色、路径与目标在同一个地图坐标系计算。镜头返回到真实角色/当前进度位置，不能返回硬编码像素或过期目标。

### 可见、可达、可操作、可领奖分离

- 预览可以显示奖励或远方目标，但必须标明条件，不能因为揭雾、拖动或缩放就绕过前置。
- 揭露范围、前置路径与费用气泡的显示分别处理。若要求展示整个下一段而费用逐个出现，必须实际渲染所有应出现的点位，费用只跟随当前允许操作的对象。
- 奖励预览点击仅展示条件；解锁后才进入真实领取，领取记录防止重复发放。

### 路径与镜头演示

- 从当前存档计算下一目标与中间有效路径点；要求逐点返回时，逐个经过每个未清障碍，多段障碍按对象或分段计点以规格为准。
- 分别定义揭雾、定位目标、停留、沿路径返回和恢复操作；不能用一次瞬移或仅滚到终点冒充整段路径演示。
- 自动触发与手动重播共用路径计算；重播不改变资源或任务完成记录。
- 明确跳过、拖动、缩放、重复点击、切图、无下一目标和减少动态效果的行为；终止后清理路径层，恢复正确数量的费用气泡和操作状态。
- 已完成最终节点时按规则交付奖励或返程目标，不为演示方便追加必走路段、重复确认或强制传送。

## 3. 任务收集与进度反馈（仅适用时）

- 明确每个数字统计什么：本件获得数、该任务目标数、所有任务收集数、剧情节点数、大奖条件分别定义，不能共用一个“进度”变量凑界面。
- 若设计采用“入口气泡 + 上方任务提示”，气泡显示本件图标/名称与本件数量，上方提示显示所属任务整体进度；具体初末值和位置按项目规格，不写死案例分母。
- 正常拾取、修复后互动、剧情自动交付等来源若更新同一收集系统，共用新增收集反馈，避免漏掉某一来源或同时播放两次飞入。
- 反馈从操作前后已经确认的拥有记录差量产生；失败和重复点击已获得对象不显示假新增。
- 连续收集排队或按明确规则合并。重渲染、镜头移动和普通 HUD 更新不能把尚未结束的气泡直接清掉；离开活动后临时表现可清理，实际进度保留。
- 领奖与收集分开；任务达成后提示可领不等于自动发放，除非规格明确自动领取。

## 4. 连续反馈的公共要求

- 动效来源和目标取自已渲染的实际控件，不能硬编码屏幕位置；缩放、窄屏和面板滚动后仍正确。
- 非阻断提示不抢点击；引导/动画锁定期间保留已定义的取消方式。多个提示不能遮住当前任务的必要操作。
- 成功、处理中、失败与恢复是不同状态；减少动态效果保留可靠终态与文字，不能把结果一起隐藏。
- 中断、重进和存档恢复不重扣、不重发、不重抽；只看到最终余额正确还不够，还应检查过程反馈是否真实出现。

## 5. 验收证据

按本次修改挑选必要检查，不为不存在的机制加测试：

| 修改对象 | 必须观察的行为 | 不能替代它的证据 |
| --- | --- | --- |
| 缩放/拖动 | 目标设备输入、边界、锚点、点击抑制、HUD稳定；承诺双指时实际送入双指事件 | 只改一个scale或测试按钮 |
| 奖励预览 | 解锁前可见不可领，点击不改余额；解锁后可领且只发一次 | 只看箱子截图 |
| 路径演示 | 目标、完整点位集合、逐点顺序、返回位置、取消后的层与气泡恢复 | 只看起点/终点两张图 |
| 收集提示 | 操作前→提交→过程→终态，单件与任务分母、不同来源、重复与失败 | 只检查计数最终相等 |
| 连续动画 | 真实中间状态、输入锁定、重渲染、轻动效和中断恢复 | CSS存在或静态截图 |
| 交付入口 | 从实际目标目录运行；若提供离线单文件，重建后再单独打开验证 | 另一目录旧构建通过 |

- 浏览器检查目标尺寸与一个合理窄屏尺寸，查看遮挡、滚动和点击区域；截图等静态面板稳定后再采集。
- 运行与修改相关的规则测试，再走核心闭环；已通过且无新改动的检查无需反复扩大。
- 报告实际通过的范围和未验证项。形式校验不能替代浏览器体验，也不能把 Demo 试算写成正式线上数值。
