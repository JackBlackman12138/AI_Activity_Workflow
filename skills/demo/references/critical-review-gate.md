# 批判性审查闸门

## 使用方法

在写脑图、画 UX 或编码前先按 [prototype-cognition.md](prototype-cognition.md) 判断范围，再检查本表的适用项。局部修改不必输出全套审查报告，也不为满足问题清单添加新机制。优先指出会让方案失效的问题，不用“可以优化”掩盖结构性缺陷。

## 0. 两门槛与六问题

### 0.1 契合门槛

- 是否保持产品定位、目标用户和题材体验一致？
- 若当前方案依附 Merge 产品，是否与其主循环关系清楚？独立非合成原型只检查其自身目标与循环，不强制引入合成。
- 新机制是否强化目标行为，而不是增加一套与主循环竞争的劳动？

不通过时停止下游制作，说明冲突点，并给出删减、换包装或改嫁接位置的替代方案。

### 0.2 落地门槛

- 开发、美术、配置、QA、运营维护和内容生产成本是否可承受？
- 工期是否覆盖核心闭环、异常边界和真实设备验收，而不只是成功路径展示？
- 学习成本、操作负担、随机挫败和经济风险是否能被控制？

没有预算、团队和工期信息时，不擅自判定通过；以最小版本继续，并把成本变量标为假设或待确认。

### 0.3 六问题

1. **10 秒理解**：玩家能否在 10 秒内说清“要做什么、怎么做、做完得到什么”？
2. **单次反馈**：一次核心操作是否有清晰的视觉、听觉、数值或状态变化？反馈强度是否与事件价值匹配？
3. **三层目标**：短期是否推动下一次操作，中期是否形成阶段里程碑，长期是否提供收集、成长或完成目标？
4. **用户与题材匹配**：机制节奏、压力、表达和奖励是否符合目标用户与产品题材？
5. **扩展空间**：能否通过内容组合、规则变量或目标变化持续扩展，而不是只增加等级和数值？
6. **证据支持**：是否有竞品、用户研究或原型数据支持？记录来源、口径和限制；没有证据时标为 `待验证`，给出最低成本验证方法。

六问题不是用主观肯定句打勾。每项使用 `通过 / 条件通过 / 不通过 / 待验证`，并附一句依据。第 6 项缺少证据不自动否决早期概念，但不得把经验判断写成事实。

### 0.4 最小概念约束

概念发散默认先限制为：

- 一个核心行为。
- 一种强即时反馈。
- 一个清楚的完成/继续条件；仅需要持续成长时再定义中长期目标。
- 最多一个必要的辅助机制。

先证明最小闭环成立，再把其他经营、收集、随机、社交或商业系统列为可选扩展。

## 1. 前提检查

- 用户假设的玩家动机是否真实存在？
- 目标、机制和奖励是否服务同一个行为？
- “增加消耗”是否只是把消耗从别处搬来？
- “提升付费”是否只有更多礼包，没有新增可感知价值？
- 竞品机制是否依赖当前产品没有的用户、经济或内容条件？

## 2. 逻辑与规则检查

- 入口 → 行动 → 反馈 → 进度 → 奖励是否闭环？
- 资源是否有明确来源、库存、消耗、回吐和净缺口？
- 倍率、概率、保底、上限和异常是否可同时成立？
- 自动升级、合成、领取、结算是否存在重复触发或状态竞争？
- 盘面满、库存不足、活动结束、断线和重复点击时会怎样？

### 2.1 规则身份检查

在需求、UE或代码制作前，确认以下实际存在的机制；不存在的项不生成新系统：

- 合成基数与链路：例如 `2碎片 → 1残缺品；2残缺品 → 1完整品`，不得凭品类惯例改成三合。
- 手动/自动边界：玩家点击什么，系统自动执行什么。
- 资源所有者：资源由活动发放，还是由主线订单/生成器等上游事件产生。
- 库存生命周期：跨关保留、重进重置、活动结束与满盘溢出。
- 目标总量、可见容量和视觉尺寸是否被错误当成同一个字段。
- 图鉴、关卡奖励、礼包和支线奖励是否职责混淆。

用户最新反馈与旧规则冲突时，先更新规则身份卡，再继续制作。

## 3. 证据分层

用下列标签记录关键陈述：

- **事实**：来自项目配置、代码、数据或可核实一手资料。
- **推测**：由事实推导，但尚未验证。
- **主观判断**：审美、偏好或经验取舍。
- **待验证**：当前缺少决定性证据。

数字结论同时记录口径、时间窗、样本、分母和对照组。无法核实时不要制造精度。

## 4. 遗漏变量

- 玩家：新手、回流、低活跃、活跃非付费、中小 R、大 R。
- 资源：期初库存、自然产量、跨活动竞争、补偿与溢出。
- 体验：理解成本、操作频率、动画耗时、打断次数、随机挫败。
- 商业：付费时机、替代消费、买完即结束、长期信任。
- 生产：策划配置、美术量、程序复杂度、QA 组合数、运营维护。
- 分析：选择偏差、幸存者偏差、活动自选择、节假日/版本混杂。

## 5. 结论格式

大型方案评审可按以下六项组织；轻玩法或局部修改只报告与目标相关的判断、缺口和处理：

1. **结论**：成立、条件成立或不成立。
2. **两门槛**：分别标记契合门槛与落地门槛的状态和依据。
3. **六问题**：逐项标记通过、条件通过、不通过或待验证。
4. **主要依据**：事实和推导链。
5. **最大风险**：最可能导致数据或体验失败的断点。
6. **替代方案**：至少一个成本更低或逻辑更稳的解释/方案。

高风险问题未解决时暂停制作；中低风险问题以显式假设继续并加入验证清单。

用户要求阶段确认时，未确认本身就是高风险断点：停在当前阶段，不提前制作下一阶段正式产物。
