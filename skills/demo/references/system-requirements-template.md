## 使用规则

- 以本模板的章节结构和需求颗粒度为基准，不照搬示例活动的具体规则。
- 本模板是内部规格槽位，不强制全量交付。按当前任务选择章节；工作清单可记录不适用原因，正式策划不保留成串 N/A 或空标题。默认功能范围见 [planning-clarity-and-ue.md](planning-clarity-and-ue.md)。
- 每条会影响规则、状态、界面、配置、数据或验收的需求分配唯一 ID，如 `LIFE-01`、`BOARD-03`。
- 内部规格记录实际相关的触发、前置、消耗、处理、状态、输出、恢复、配置、反馈和验收；埋点按已启用范围记录。正式策划将这些内容组织成功能分组、操作步骤和条件分支，不逐条复制字段清单。
- 使用 `事实 / 决策 / 假设 / 待验证` 标识来源状态。截图、竞品表现和经验不能自动当成项目事实。
- 禁止只写“同某活动”。若复用既有系统，必须给出可定位的版本、模块或链接，并列出本活动的差异项。
- 数字必须注明单位、取值范围、默认值、上下限、精度、时区或刷新时机；概率需注明是否独立抽取、权重归一方式和保底。
- 文档中的关键需求必须同步到脑图；玩家可见状态与交互必须同步到 UE；可执行逻辑必须同步到 Demo；配置与边界必须进入验收清单。
- 用户要求阶段确认时，在基本信息中记录当前闸门（需求待确认 / UE待确认 / Demo已授权 / 部署已授权）；未确认不得把后续产物标为正式版。
- 为合成基数、手动/自动边界、资源真实来源、库存生命周期、总量/可见容量/视觉尺寸建立明确字段，避免实现按品类惯例自行补全。

## 5. 系统模块需求

以下模块按实际活动选用；不存在的系统不生成空模块。“需求原子”是内部覆盖检查格式，面向下游的正文按功能与过程组织。

### 5.1 棋盘区域

- 行列、格子 ID、初始物品、锁定状态和解锁条件。
- 锁定棋子能否通过同级合成解锁；锁定地块的点击反馈。
- 解锁后棋盘移动方向、格数、顺序与动画；被挤出棋子的去向。
- 棋子移动、交换、合成、删除、出售、气泡、撤销和误触保护。
- 主链与支线库存是否跨关/跨日保留；进入新关是否清空、补足或完全不处理。
- 若目标或棋子来自队列，定义总量、可见容量、固定尺寸、清除 N 后补 N、剩余不足和补位后相邻规则校验。

### 5.2 主线棋子生成器

- 单次消耗、点击条件、掉落数量与掉落序列。
- 生成器等级、升级道具、等级上限及效率变化。
- 资源不足、棋盘空间不足、礼包触发与频控。
- 产出超过空格时的待领奖区 / 溢出处理。

### 5.3 主线合成链与特殊棋子

- 棋子链、合成数量、最高级处理、首次获得和解锁。
- 宝箱、障碍、体力、钻石、金币、加速、次数类棋子的行为。
- 不可删除 / 不可出售 / 锁定棋子清单及原因。

### 5.4 支线棋子生成器

- 充能材料、充能方式、充能状态和固定 / 随机产出。
- 未充能点击、重复充能、满级材料、棋盘无材料时的反馈。
- 生成后是否需要再次充能，以及状态如何在 UE 中表达。

### 5.5 待领奖区

- 进入来源、容量、展示数量与领取方式。
- 多物品同时进入时的确定性排序；同优先级的次级排序。
- 棋盘空间不足、退出重进、跨端、断线和活动结束时的处理。

### 5.6 图鉴 / 收集

- 图鉴系列、棋子范围、解锁状态、待领奖状态和已领奖状态。
- 首次产出 / 首次合成的认定；历史获得是否追溯。
- 单节点、单系列和全图鉴奖励的领取顺序与自动领取规则。
- 红点和进度公式；活动重开时是否重置；结束未领奖处理。

### 5.7 进度、奖励与自动升级

- 短循环进度、阶段里程碑、最终目标和完成条件。
- 手动 / 自动领取，奖励溢出，重复触发与幂等处理。
- 自动升级与手动升级二选一；若并存，明确优先级和入口。

## 6. 防卡死与异常恢复

### 6.1 卡死检测

- 检测时机：`[操作后 / 进入页面 / 定时]`
- 卡死定义：`[满盘且无可合成 / 缺关键棋子 / 路径阻塞等]`
- 误判保护：`[待领奖区、生成器、礼包、可领取奖励是否计入]`

### 6.2 恢复手段

- 删除 / 出售规则与不可删除清单。
- 免费兜底、广告、软货币、等待、回收箱、重排或客服补偿。
- 防止兜底被套利的频控、日志和幂等规则。

### 6.3 数据与存档异常

- 断线重连、跨端覆盖、版本回滚、配置缺失、资源扣除成功但发奖失败。
- 明确客户端预测、服务端权威、重试策略和补偿来源。
