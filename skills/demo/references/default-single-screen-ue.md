# 无 Figma 时的默认单屏 UE 规范

## 适用条件

用户跳过 Figma、当前环境没有可写 Figma MCP，或只要求直接制作 Demo 时，先按 [prototype-cognition.md](prototype-cognition.md) 判断机制，再选择本规范适用部分。缺少 Figma 不等于采用独立合成盘布局。若用户给出明确交互需求、现有产品规范或界面截图，以用户最新要求为准。

## 默认信息结构

优先以一个操作主界面承接简单闭环；复杂玩法按实际流程拆分。以下为候选区域，不存在的机制直接省略：

1. **顶部栏**：当前玩法名、必要帮助、关闭或返回；仅限时玩法显示倒计时。
2. **主题场景**：主视觉、当前资源、倍率/档位（如有）、主要操作按钮。
3. **目标区**：当前目标与进度；仅有成长或收藏时显示对应入口，不默认合成链。
4. **操作区**：根据机制使用棋盘、地图、拼图、选择面板等。棋盘尺寸来自规格，不能预设所有原型为6×6或7×7。
5. **轻量工具区**：独立低权重 Debug 与重置；仅存在外部资源接口时提供对应事件模拟。

简单单循环优先避免无必要的页面跳转；存在分区或分阶段流程时按需求设计，不能强制塞进同一屏。奖励、升级、资源不足、规则提醒、确认和错误使用小弹板、Toast 或屏幕内浮层，并自动渐入渐出。只有会造成不可逆损失的操作才使用需要确认的模态弹窗。

## 交互选用

以下合成、链路、图鉴交互只用于存在这些机制的项目；其他玩法按自身输入、反馈与结果规格实现。

- 支持把棋子拖到同级同类棋子上合成，拖到空格移动。
- 同时保留“点来源—点目标”操作，兼容触控和不熟悉拖拽的体验者。
- 合成链可水平拖动/滚动；获得新等级时自动滚到对应节点并高亮。
- 自动升级或自动领奖使用约 2～3 秒的小提示板，出现后自动淡出。
- 资源不足、空格不足和无效合成使用 1～2 秒 Toast，不打开新页面。
- 图鉴和 INFO 使用同屏模态层；关闭后回到原棋盘状态，不重置操作进度。

## 容量与固定尺寸

- 把总内容量、当前可见容量和对象视觉尺寸分开设计；配置上限不等于必须同屏塞满。
- 球、棋子、卡片等核心操作对象默认保持固定尺寸与点击热区。空间不足时减少可见数量，把其余内容放入稳定队列或滚动容器。
- 清除 N 个队列对象后补入 N 个；后备不足时只补实际剩余量。补位不得改变面板高度或压缩其他操作区。
- 在最窄目标宽度和最大内容量下截图验收；不要只检查内容较少的教学状态。
- Debug 独立放在低权重区域，用于模拟主线订单、随机产出、指定边界、跳关和重置，不与正式入口混淆。

## 动效基线

- **产出**：来源按钮压缩回弹；棋子沿短弧线或缩放飞入目标格，落点弹跳。
- **合成**：来源棋子向目标收拢；结果棋子 `0.75 → 1.18 → 1`，伴随光圈、星屑或水花；总时长约 450～700ms。
- **新节点**：合成链节点高亮两次，并平滑滚动到中间。
- **里程碑**：小弹板 `opacity 0 → 1 → 0`，轻微缩放，停留不超过 3 秒。
- **按钮**：按下 80～120ms，禁用态仍清楚显示原因。
- 尊重 `prefers-reduced-motion`，减少飞行距离和大幅缩放。

## 视觉基线

- 使用有明确主题的背景、场景和材质层次，不交付纯白后台卡片式界面。
- 主按钮、资源、当前目标和棋盘形成清晰视觉顺序；装饰不得遮挡操作。
- 保持背景、操作主体与反馈的层级清楚；棋子层只在当前机制存在棋子时使用，不为凑层级新增对象。
- 可使用 CSS 插画、渐变、SVG、开源图标或用户提供素材；不得把低清截图直接当正式资源。
- 默认优先移动端纵向单屏，同时在桌面居中展示；不让主操作区横向溢出。

## 例外

- 图鉴内容过多时可使用可滚动模态层，不跳转新页面。
- INFO 可使用简短分步说明；不要做长篇教程页。
- 只有用户明确要求多页面、完整商城、叙事章节或复杂地图时才扩展页面结构，并说明增加的制作和理解成本。
