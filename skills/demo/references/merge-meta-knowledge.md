## 1. 使用与更新规则

本文件是可迭代知识库，不是无条件成立的设计定律。每条知识使用以下字段：

- **状态**：产品事实 / 外部事实 / 经验假设 / 待验证。
- **适用范围**：何种 Merge 产品、玩家或活动。
- **反例/限制**：何时不成立。
- **依据**：项目数据、配置、用户确认、竞品观察或推理。
- **影响**：对 UX、数值、技术或验证的要求。
- **更新时间**：YYYY-MM-DD。

新增前查重并检查冲突。若新证据推翻旧结论，保留旧条目的“已废弃”说明和原因。

## 2. 基础主循环

### 2.1 通用循环

- **结论**：常见 Merge 循环可抽象为 `获取生成资源 → 生成低阶物 → 合并升级 → 完成订单/目标 → 获得资源与进度 → 再次生成`。
- **状态**：经验假设。
- **适用范围**：以二合一或多合一盘面为核心的休闲 Merge 游戏。
- **反例/限制**：无订单、纯探索或 Merge 仅为轻量子玩法的产品。
- **依据**：品类结构抽象；需用当前产品规则确认。
- **影响**：活动应明确嫁接到循环中的哪一段，避免创建互不相干的第二套劳动。
- **更新时间**：2026-08-11。

### 2.2 行为空间约束

- **结论**：盘面空间同时承担操作容量、决策压力和节奏控制；新增支线棋子会占用机会成本。
- **状态**：经验假设。
- **适用范围**：共享主盘或有限活动盘。
- **反例/限制**：无限背包、自动收纳或独立无限盘。
- **依据**：规则推导。
- **影响**：设计支线产出时必须定义满盘、溢出、回收和清理成本。
- **更新时间**：2026-08-11。

## 3. 活动嫁接位置

### 3.1 主线行为牵引

- **结论**：活动应说明它推动的是订单、生成器、体力、盘面整理、合成链还是回访频率。
- **状态**：经验假设。
- **适用范围**：运营活动与主线共享行为或资源时。
- **反例/限制**：完全独立且目标是玩法换气的活动。
- **依据**：目标—行为链路推导。
- **影响**：指标需能区分新增行为和从其他系统迁移的行为。
- **更新时间**：2026-08-11。

### 3.2 独立活动盘

- **结论**：独立活动盘能隔离主线经济，但会增加学习、配置、美术与 QA 成本。
- **状态**：经验假设。
- **适用范围**：有独立地图、棋子链或专属资源的活动。
- **反例/限制**：已有成熟复用框架时边际成本较低。
- **依据**：生产与经济隔离的权衡。
- **影响**：立项时同时评估复用率、入口复杂度与活动间竞争。
- **更新时间**：2026-08-11。

## 4. 盘面与合成规则

### 4.1 固定网格

- **结论**：Web 原型中必须同时固定列数、行数、格子宽高和按钮默认内边距，避免内容或合成后盘面跳动。
- **状态**：外部事实。
- **适用范围**：CSS Grid 实现的固定盘面 Demo。
- **反例/限制**：自适应非方格布局。
- **依据**：钓鱼合成 Demo 的已复现布局问题。
- **影响**：使用显式 `grid-template-columns`、`grid-template-rows` 和固定 aspect ratio/尺寸。
- **更新时间**：2026-08-11。

### 4.2 操作方式

- **结论**：桌面端优先支持拖拽移动与同级合成，并保留点击来源—目标作为兼容；移动端使用 Pointer Events 或等价触摸方案。
- **状态**：经验假设。
- **适用范围**：需要可玩验证的 Web Merge 原型。
- **反例/限制**：只验证数值、不验证操作的模拟器。
- **依据**：交互可达性与原型测试需要。
- **影响**：需处理空格、非法目标、拖出区域和重复事件。
- **更新时间**：2026-08-11。

### 4.3 长合成链

- **结论**：合成链应允许查看完整节点，并反馈当前最高发现位置；长链可横向滚动或拖动。
- **状态**：经验假设。
- **适用范围**：合成链本身承担目标感或图鉴功能的活动。
- **反例/限制**：链条对玩家隐藏、主要目标来自订单时。
- **依据**：目标可见性推导。
- **影响**：新节点出现时滚动到可视区并短暂高亮，避免永久强打断。
- **更新时间**：2026-08-11。

### 4.4 总量、可见容量与视觉尺寸

- **结论**：队列型目标的总量、当前可见容量和单个对象视觉尺寸必须分开配置；空间不足时优先减少可见数量并使用后备队列，不为塞满配置上限动态缩小操作对象。
- **状态**：外部事实。
- **适用范围**：泡泡链、目标队列、订单队列、横向卡片和其他固定操作窗口。
- **反例/限制**：对象缩放本身是明确玩法或响应式设计规范时。
- **依据**：泡泡远征 Demo 的浏览器布局与交互验证；动态缩小导致同一对象跨状态尺寸不一致。
- **影响**：需求与配置分别提供 `total_count`、`visible_capacity`、`visual_size`、后备排序和清 N 补 N；验收最大总量与最窄宽度。
- **更新时间**：2026-08-18。

### 4.5 障碍格与半解锁格状态机

- **结论**：当前扭蛋机独立合成线使用 `完全障碍格 → 半解锁格（带预置棋子）→ 普通格`。完全障碍格遮盖内容且不可操作；玩家在其上、下、左、右相邻格完成合成后，障碍格转换为带预置棋子的半解锁格；玩家再用同链同等级棋子与预置棋子对碰，按正常合成规则生成高一级棋子，同时将该格永久转换为普通格。
- **状态**：产品事实。
- **适用范围**：用户确认的扭蛋机独立合成线；其他活动只有在规则明确复用时才采用，不作为所有 Merge 棋盘的默认规则。
- **反例/限制**：斜角是否触发、一次合成是否影响多个障碍、障碍触发次数、半解锁合成能否继续触发相邻障碍仍需活动配置明确；只用视觉遮罩但底层仍可放置的实现不符合该规则。
- **依据**：用户于 2026-08-20 明确指定的活动规则。
- **影响**：需求与实现必须分别保存格子状态和棋子状态，定义预置棋子、移动限制、邻接事件、转换幂等、满盘处理和重连恢复；QA 验收可达路径、错误棋子拒绝、连锁触发和最坏随机产出下的防卡死。
- **更新时间**：2026-08-20。

## 5. 资源经济

### 5.1 资源账本

- **结论**：至少记录期初库存、自然来源、活动新增来源、自然消耗、活动新增消耗、奖励回吐和净缺口。
- **状态**：经验假设。
- **适用范围**：所有会影响主线或付费资源的活动。
- **反例/限制**：纯展示、无资源变化的活动。
- **依据**：经济闭环要求。
- **影响**：没有数据时输出变量与公式，不伪造结果。
- **更新时间**：2026-08-11。

### 5.2 倍率

- **结论**：若倍率表示批量执行，则 `×N` 应明确为消耗 N 份资源并产出 N 次结果；概率是否独立判定、支线产出上限和空位不足处理必须显式定义。
- **状态**：产品规则范式。
- **适用范围**：批量钓鱼、开箱、生成或采集。
- **反例/限制**：倍率改变品质、收益系数或风险而非执行次数时。
- **依据**：歧义消除与 N:N 资源守恒。
- **影响**：UI 同时显示倍率、总消耗和总产出；执行前校验资源与容量。
- **更新时间**：2026-08-11。

### 5.3 上游资源来源不等于活动赠送

- **结论**：若活动资源由主线订单、主线生成器或其他上游系统产生，活动应接收幂等事件并管理库存，不应在进关时再次补发“刚好通关”的资源。
- **状态**：产品规则范式。
- **适用范围**：活动通过主线行为牵引玩家、资源跨系统流入时。
- **反例/限制**：已确认的首登赠送、教学固定发放或独立活动盘自有生成器。
- **依据**：资源所有权与重复发放风险推导；泡泡远征资源来源修正。
- **影响**：需求记录事件、所有者和重试；Demo Debug 模拟上游事件，不伪造活动内免费来源。
- **更新时间**：2026-08-18。

### 5.4 随机产出与防卡死并存

- **结论**：随机产出不应写成固定序列，防卡死也不等于每关精确配平。可用需求权重、连续同色上限、累计偏差/缺色保底与跨关库存，在随机感和可完成性之间取平衡。
- **状态**：经验假设。
- **适用范围**：多颜色/多类型材料由订单、生成或掉落随机产出的活动。
- **反例/限制**：纯教学关、严格谜题或服务端指定序列。
- **依据**：泡泡远征随机碎片方案与批量模拟；具体阈值仍需真实数据校准。
- **影响**：数值给公式和区间，不伪造精确线上值；配置提供权重、保底、库存折算和可复现种子。
- **更新时间**：2026-08-18。

## 6. 进度、奖励与收集

### 6.1 自动升级

- **结论**：当升级条件只是“获得指定链节点”且没有资源取舍时，自动升级通常比再加一次确认更直接。
- **状态**：经验假设。
- **适用范围**：升级无分支、无消耗决策且目标明确。
- **反例/限制**：升级会消耗稀缺物、改变策略或存在多路线选择。
- **依据**：减少无意义操作。
- **影响**：触发时给短时反馈，定义重复获得和跨级触发规则。
- **更新时间**：2026-08-11。

### 6.2 图鉴

- **结论**：图鉴需要区分“查看发现进度”和“领取奖励”；若高频领取会打断核心循环，应采用自动发放或低频里程碑领取。
- **状态**：经验假设。
- **适用范围**：合成链发现、收集或宝箱支线。
- **反例/限制**：领奖本身是核心庆祝节点。
- **依据**：操作节奏与打断成本。
- **影响**：UX 明确已发现、未发现、当前节点和可领奖状态。
- **更新时间**：2026-08-11。

## 7. 商业化

### 7.1 付费承接

- **结论**：付费点应解决已被玩家感知的时间、容量、资源或确定性缺口，并避免购买后立即结束活动。
- **状态**：经验假设。
- **适用范围**：以资源缺口承接付费的限时活动。
- **反例/限制**：纯装饰、订阅或广告商业化。
- **依据**：价值感与持续参与推导。
- **影响**：评估付费后剩余目标、主线替代消费和长期留存护栏。
- **更新时间**：2026-08-11。

## 8. UX 与反馈

### 8.1 高频循环减少阻断

- **结论**：高频动作的结果尽量原位反馈或直接入盘，避免每次出现领奖确认弹窗。
- **状态**：经验假设。
- **适用范围**：短间隔钓鱼、生成、合成和收集。
- **反例/限制**：稀有大奖、重要叙事或合规确认。
- **依据**：操作时长与重复打断成本。
- **影响**：使用飞入、落格、高亮和短 toast；稀有事件再提高表现层级。
- **更新时间**：2026-08-11。

### 8.2 动效层级

- **结论**：普通产出用局部反馈，新发现/升级用 1–3 秒强化反馈，大奖才使用可阻断庆祝。
- **状态**：经验假设。
- **适用范围**：高频休闲活动。
- **反例/限制**：品牌或叙事要求更强表现时。
- **依据**：反馈强度与事件稀有度匹配。
- **影响**：定义跳过、自动关闭和连续触发队列。
- **更新时间**：2026-08-11。

## 9. 数据验证

### 9.1 基础漏斗

- **结论**：至少追踪曝光、进入、首次核心操作、短循环完成、中期里程碑、最终完成与付费承接。
- **状态**：经验假设。
- **适用范围**：限时活动。
- **反例/限制**：常驻系统需要改用 cohort 和长期留存。
- **依据**：行为漏斗方法。
- **影响**：按玩家层级、库存和活动日拆分，避免平均数掩盖问题。
- **更新时间**：2026-08-11。

### 9.2 因果谨慎

- **结论**：活动期消耗或收入上涨不能单独证明活动创造增量，需检查对照、替代消费和活动后回落。
- **状态**：分析原则。
- **适用范围**：活动复盘和 A/B 测试。
- **反例/限制**：无可用对照时只能降低结论置信度。
- **依据**：混杂与迁移效应。
- **影响**：记录基线、活动间重叠、节假日、版本与人群自选择。
- **更新时间**：2026-08-11。

### 9.3 随机规则的约束测试

- **结论**：随机序列与掉落不能只看一次成功样本；应运行数百至上千轮约束或蒙特卡洛测试，报告长度、相邻上限、最大偏差、最低供给、保底与最坏样本。
- **状态**：外部事实。
- **适用范围**：含洗牌、权重池、概率、保底或动态补位的 Demo 与配置验证。
- **反例/限制**：完全确定性的教学序列仍需边界测试，但无需蒙特卡洛。
- **依据**：随机洗牌曾在少数路径把同色组留到末尾形成三连，批量测试复现并推动改为受约束回溯洗牌。
- **影响**：提供自动验证脚本或测试入口；明确模拟不能替代真实玩家数据。
- **更新时间**：2026-08-18。

## 10. 常见风险

- 机制层数增加但每层都没有新的决策。
- 支线棋子挤占盘面，却没有整理或回收方案。
- 概率、倍率和保底文案与真实算法不一致。
- 为了展示奖励频繁弹窗，拖慢高频循环。
- 只看总体完成率，忽略库存和付费层级差异。
- 把竞品表层 UI 当成机制成功的原因。
- 只计算活动收入，不计算主线和其他活动的替代损失。
- 原型只覆盖成功路径，没有满盘、资源不足、重复触发和重置。
- 把配置的最大总量误当成同屏容量，为塞满而缩小对象。
- 把上游订单产出的资源在活动进关时再次“直接给玩家”。
- 随机规则只看一个样本，没有批量验证少数非法序列。
- 本地源目录可运行，但复制或上传 GitHub 时漏掉 `src/` 等嵌套依赖。

## 使用前的范围判断

本知识库只处理实际涉及 Merge 的产品与模块。原型类型、规模与交付深度先按 [prototype-cognition.md](prototype-cognition.md) 判断；非合成轻玩法或单个功能改动，不因本知识库存在而增加合成盘、棋子链、长期成长或付费系统。
