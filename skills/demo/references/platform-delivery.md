# Activity Studio 完整 Demo 交付规范

本入口用于已有确认策划的实现阶段，继承“玩法与活动原型工坊”的规则、交互和验收原则。平台负责需求清单、实现、审查与有界修正，不重新做概念设计，不创建 Figma，不部署。不用“最小可玩”缩减用户已经确认的活动范围。

## 完整性
- 实现策划规定的全部区域、阶段、入口、弹窗、奖励、收集线、资源规则与结束流程。小地图样片、永久锁住的后续区域、只有提示的入口、改计数模拟真实行为，都不能替代完整实现。
- 数量、初始状态、前置、免费/耗费、自动/手动、拥有/安装、收集/领取分开表达。跨图返回、已领取、资源不足、重复点击和重进都必须有行为。
- 外部主游戏账户可用独立 Debug 模拟上游事件；活动自身的流程不能放进 Debug 里替代实现。未知正式数值用明确列出的演示假设，不缩减系统。

## 视觉与交互
- 先从策划图文确定界面组成、主题、布局、关键物体轮廓和视觉层次，再实现。文档里的表格截图不是正式美术素材，参考图上的旧数字不是规则来源。
- 主场景、角色、障碍、建筑、奖励和主功能入口使用统一风格的内联 SVG/CSS 插画或用户提供的有效素材。不能用 Emoji、文字方块或后台表单充当游戏主视觉。
- 390×844 竖屏主视图，HUD 与地图分层；复杂地图允许世界坐标拖动，不能为了单屏缩减区域和内容。弹层可滚动，不遮住关闭按钮。
- 按下、处理中、结算成功、失败和恢复都有可见反馈；动效呈现已确认状态，不在动画回调再次扣费、随机或发奖。支持减少动态效果。
- 地图拖动与对象点击必须分开：不要在地图容器每次 pointerdown 时立即 setPointerCapture，否则内部按钮的 click 可能被重定向到容器。先排除 button 等交互目标，或越过明确拖动阈值后再捕获；引导时允许的按钮仍须收到真实点击。
- 按钮按下态必须保留原定位变换：例如地图对象通过 translate(-50%,-50%) 定位时，不能被通用 button:active 的 translateY 覆盖，否则按下瞬间移出指针，click 无法触发。按下反馈改变亮度、阴影，或在原变换上组合 scale。

## 配置与源码
- 平台注入 window.ActivityStudio.tables[表ID]（含 fields、rows），config 为主表兼容入口，track(type,rowIndex) 用于主表节奏事件。不得定义、覆盖或写入 ActivityStudio/config/tables；数值和内容数据从计划中的表读取。
- 节奏看板只接收 step_enter、step_complete、session_complete。主表必须是主要进度节点表，进入/完成节点时以主表零起始行索引调用 sdk.track("step_enter", index)/sdk.track("step_complete", index)，全部完成时调用 sdk.track("session_complete")。session_start 由平台发送，不自造 story_complete 等事件名。
- 活动参数、地图与节点、条件、掉落、奖励序列、任务、收藏、商店、文案、表现参数等按实际机制建表。保留已保存表中的字段和值。缺省演示值逐项列入 assumptions，不能默默写成线上值。
- 配置字段只能是 string/number/boolean；数组与嵌套内容以 JSON 字符串字段表达，description 写清结构和关联键。引用必须可追溯，不使用不存在的行 ID。所有计划表均需被实现读取。
- 按平台当前步骤输出工程清单、单个文件、测试场景或局部修改。源码按规则、状态、视图、输入和反馈拆分为工程内模块，允许相对 import/export，由平台编译成离线 HTML；不使用外部 npm 包、远程字体或本机路径。浏览器离线可运行；规则、状态、渲染、输入、反馈分区，保留需求 ID 注释。
- 本地存储在沙箱中可能不可用，必须 try/catch 并有内存回退，不因此白屏。无需联网即可试玩。
- 平台实际执行编译、独立浏览器场景和截图核对，结果会反馈到修复步骤。每个场景从全新页面开始，需包含入口、封面、引导和弹层关闭等前置动作，不依赖其他场景留下的状态。只能基于平台返回的工具结果描述验证状态，不能伪造已测试。
