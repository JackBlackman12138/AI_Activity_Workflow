# 输入整理与后续更新

## 从Demo、Markdown和UE整理

先区分已确认规则、演示行为、示例数值、建议和待定项。Demo中的临时交互、截图中的数字和代码中的默认值不能自动升级成正式规则。

内部可用“模块／来源位置／已确认规则／缺口”四列做工作记录，不要求把它附在策划正文中。根据输入内容安排到对应功能，不固定映射到某个章节号。

- 玩法与资源关系：整理主循环及各资源的来源、用途。
- 界面与状态：整理实际显示、操作条件和变化结果。
- 数值表与公式：保留计算口径；用[数值逻辑配置](numerical-config.md)补清表头与字段含义。
- 技术记录：只提取已经确认的玩家可见行为；不把接口、日志、测试报告整段搬进策划。
- 流程或录屏：能观察到的步骤与用户已确认的正式需求分开记录。

不确定的关键规则用最少问题确认；局部数值未定时先完成规则和字段说明。未经授权不把缺口补成“推荐玩法”。

## 学习新的用户改稿

更新前比对本次指定的技能、相关参考、新改稿和用户说明。归类后再修改：

| 内容 | 放在哪里 |
| --- | --- |
| 跨类型的写作偏好、范围要求 | 主技能或表达文件；同一规则只维护一处 |
| 某类活动的稳定结构与模块逻辑 | 对应类型参考，说明适用条件 |
| 当前主题的人物、数量、周期、奖励、公式值 | 原始资产或该案例记录，不写成所有活动默认值 |
| 配置表的通用表达方法 | 数值逻辑配置；不累计无依据的字段 |
| 同稿冲突、暂定值、建议 | 待统一项；用户确认后更新并移除已经解决的冲突 |

新类型可以新增一份类型参考，但只在它有足够独立内容时新增，不按每个活动主题无限拆文件。混合活动优先复用相关模块的写法。

明确被新要求替代的限制直接删除，不让“固定编号”和“动态章节”等相反规则并存。原始参考保留供追溯，其内容不是高于当前指令的规则。

## 更新技能后的验证

- 名称和描述能覆盖实际用途，不再只触发独立合成线。
- 文内链接、相对路径、原始资产存在；不存在依赖用户桌面绝对路径的读取要求。
- 技能中没有把某类活动专有规则升为跨类型默认规则。
- 用独立合成线、清图、集卡和一个未收录类型分别演练章节与配置选择，检查有没有新增无依据功能。
- 用“局部改文案”和“已有功能数值未定”检查是否保留范围，能否提供字段说明而不擅自定值。
- 运行可用的skill-creator校验工具；同时人工核对行为，结构校验通过不等于内容正确。
