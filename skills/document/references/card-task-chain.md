# 集卡任务链

来源：[集卡任务链参考Word](../assets/MC集卡任务链活动参考.docx)。本例以有效金币推进任务节点，奖励主要为卡包；不能从“集卡”一词推断有合成棋盘或独立图鉴。

## 结构与功能

原稿为短活动：活动开启 → 主界面与任务链底层逻辑 → 奖励及弹窗 → 关闭 → 换皮与难度配置。已有数据指标内容，不应作为空模板章节删除。

| 模块 | 原稿记录及写作重点 |
| --- | --- |
| 周期 | 后台配开始结束时间，集卡周期内可配置多期；原稿写每日03:00刷新任务并重置进度。这不是其他类型的日切规则 |
| 首次开启 | 直接打开活动主界面，无开启封面；不能照搬合成线封面 |
| 入口 | 主棋盘订单前，展示倒计时、当前节点奖励和金币进度。未达标仅增长进度；有待领奖时显示领取按钮、红点数量 |
| 节点推进 | 订单结算后的有效金币推进任务；达到一个或多个节点形成待领奖。区分本次获得金币、节点需求、剩余进度及待领奖数量 |
| 传送带 | 本例6个固定托盘展示位，奖励随领奖推进；多个节点完成可一并表现及领取。实际节点结束后补空托盘，空托盘不是新任务 |
| 领奖 | 玩家主动触发领取，不因完成节点就强弹领奖。单节点入口点击路径在原稿中有不同描述，需确认 |
| 多档完成 | 根据已完成节点数推进托盘，显示本批奖励，再切换到下一节点及剩余进度；不要自行增加逐档强制弹窗 |
| 最终大奖 | 奖励配置标明哪个节点为大奖；最后奖励领取后关闭活动并移除入口。不能把空托盘继续计入任务 |
| 到期 | 原稿活动内不自动关闭，玩家关闭后结束；活动外移除入口，未领道具走补领。不可用界面表的泛化描述覆盖这一差异 |
| 换皮与难度 | 按活动ID、时间、皮肤与难度配置；原皮作为默认皮肤。示例日期和拼接格式仅作原稿记录，不规定研发编码 |

## 数值口径

原稿要求按R层读取金币需求系数，给了R0、R1、R2及R10的示例值。不要补齐省略层的系数，也不要按等差估算。

原稿取整：金币计算结果四舍五入，小于100精确到个位，大于等于100精确到十位。保留阈值与精度，但原稿未把基础需求、有效金币和系数的完整公式及取整顺序写全；需明确应用对象后才能正式定稿，不套用清图的订单经验公式。

按[数值逻辑配置](numerical-config.md)提供简明表头：分R系数、节点需求与奖励，以及已经写出的活动皮肤/难度关系。没有依据的动态难度、概率、保底或经济仿真都不加。

## 已有数据分析范围

原稿按R0～R10看活动参与、各档/最终完成、节点耗时和流失、订单及体力消耗、奖励领取及卡包投放。这些可在整理当前稿时保留；不据此给所有活动默认新增埋点，也不发明事件名、上报协议或目标值。

使用该参考前核对[待统一项](reference-conflicts.md)中的主动领取、到账时机、单档入口路径、到期关闭与首次开启表述。
