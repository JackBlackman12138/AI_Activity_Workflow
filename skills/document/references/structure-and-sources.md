## 结构怎么选

三份稿的共同习惯是：先交代活动目的与目标，再说明整体流程，最后按模块展开功能；界面和配置放在所属模块附近。具体目录不同：

| 类型 | 原稿结构特点 | 新建时的处理 |
| --- | --- | --- |
| 独立合成线 | 基础信息、影响、目的、目标、概述、UE；第9章展开活动进行及棋盘模块 | 同类活动可沿用；没有图鉴或待领奖区就不新增，不固定9.2.5–9.2.8 |
| 体力清图 | 与独立合成线前部相近；第9章分别展开地图、剧情、手册、扭蛋、体力、循环关卡、奖励和结算 | 多个长线目标分别说明，不将全部玩法挤入“活动进行”一节 |
| 集卡任务链 | 目的、目标、影响、流程后直接进入第8章功能详细说明；另有换皮及数据分析内容 | 保留短活动的紧凑结构，不额外补一套名词、独立棋盘或UE章节 |

沿用用户格式指标题层级、表格组织、图文关系和阅读顺序，不是永久固定章节号。局部修改保留现有编号；整体整理删除不适用内容后顺排编号，同步目录和交叉引用。

## 有内容才保留的章节

- 变更记录、沟通群、Demo、录屏、UE和相关文档：只放用户提供的有效内容，不造链接、修订人或历史记录。
- 活动目的和目标：复述已有目标，不自行补付费提升、留存提升或目标比例。
- 名词解释：只解释实际使用且易混淆的词，不逐个定义普通按钮和常识。
- 影响范围：只列资料已提到的受影响功能，不默认所有活动都影响订单、商店或玩家分层。
- 流程图：原稿有该部分或用户要求时，根据已知流程整理；缺少规则的路径不补造。
- 功能详情：按真实模块及其关系安排，可以包含开启、玩法、奖励、关闭、开关，但无依据的部分不加。
- AB、埋点、数值、多语言、付费：资料里已有实质内容或用户明确要求时保留。参考稿中的空标题不等于待写任务。

必要的功能配置表可以放在模块内，无需专门新增“数值分析”一章。现有文档中有内容的后置章节不能因为旧技能“默认只到第9章”而删掉；例如集卡稿已有数据指标，清图稿已有礼包逻辑。

## 常用表格

| 用途 | 参考表头 |
| --- | --- |
| 变更记录 | 版本号／修订时间／修订人／主要修订内容 |
| 影响范围 | 受影响功能／影响内容 |
| 名词说明 | 术语／说明／获取方式；有实际图片才加图示 |
| 主界面 | 编号／功能模块／描述／图示；图片集中放在表前时可去掉图示列 |
| 功能图文 | 功能模块／描述／图示 |
| 状态与操作 | 状态／显示与操作 |
| 资源来源 | 来源／规则／数值状态 |
| 奖励结算 | 对象／到期处理 |
| 弹窗 | 弹窗／触发／队列与中断规则 |
| 配置字段说明 | 中文字段／字段说明；需要时增加参考字段名、类型或示例 |

表头只是选用形式。不要在没有图片、对照关系或重复字段时保留空表格。连续流程用分组列表即可。
