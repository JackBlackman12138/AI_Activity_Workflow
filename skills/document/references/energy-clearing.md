# 体力清图

来源：[体力清图参考Word](../assets/MC体力清图活动参考.docx)。本例为广场加分区探索，并组合剧情、任务手册、扭蛋收藏与兑换。新清图活动不必包含这些全部模块。

## 核心结构

原稿按“地图与清障 → 剧情推进 → 任务手册 → 扭蛋及收藏 → 活动体力 → 通关后循环 → 奖励 → 结束”展开。多个长线目标独立计数，不合并成一个收集进度。

原稿具体值：9天、中央广场加5区、17剧情点、5匹木马、5品质共25收藏品、初始体力150、恢复上限150、6分钟恢复1点。均为本案例资料，不作为其他清图活动默认值。

## 模块记录

| 模块 | 本例逻辑与写作重点 |
| --- | --- |
| 切图与回访 | 保存所在区域进度；已开放旧区可回访。进入、传送与已清道路通行不耗体力。获得木马后先留在原区，玩家主动回广场后才自动安装；不合并成自动返城 |
| 清障与分段 | 每次只清一段并扣该段费用；保存各段进度，非末段更新破损外观及下段费用，末段移除阻挡。费用、分段掉落与剧情触发分别讲清 |
| 操作气泡 | 首个和连续后续障碍的费用气泡按原稿自动展示；点击其他对象会收起原气泡，同一时间一个气泡。区分点选对象和确认消耗 |
| 地图互动 | 拾取、修复、提交材料、修复后互动、宝箱分别说明；不要把“修复完成”和“点击收集”当同一事件 |
| 迷雾与路径 | 看见目标不代表道路已通；任务定位和路径提示不替玩家清障。原稿宝箱在迷雾中可见但未到达不能领取 |
| 剧情 | 只在指定剧情事件完成后计点，普通清障不逐次增加剧情点。道具拥有与安装分别记录，剧情大奖和五木马任务奖励分别判断 |
| 任务手册 | 任务组定义收集目标及奖励；目标表说明收集成功事件、来源与定位。进度按已获得目标统计；本例全收集条件不要求先领取各任务奖励 |
| 扭蛋序列 | 单抽读取一项；批量逐项推进并逐项更新拥有记录，同批第二次出现相同玩具按重复处理；本期记录序列及读取位置 |
| 倍率 | 本例×1/×3/×5/×10代表读取1/3/5/10项，花费N/3N/5N/10N张券。不能取一项结果乘倍数；券不足不自动降档 |
| 玩具收藏 | 首次获得点亮；重复按品质转成活动体力。玩具、品质转化、收藏组奖励分别有配置关联；全收藏与分组奖分别记录领取状态 |
| 兑换商店 | 本例集齐全部玩具后解锁，不要求已领收藏奖或完成剧情。仍保留扭蛋，与兑换共用券余额；兑换不推进抽取序列，不改变收藏状态 |
| 活动体力 | 与主游戏体力区分；本例自然恢复到上限暂停、离线补算，奖励可超过恢复上限。订单按R分层系数换算活动体力 |
| 通关后循环 | 本例剧情结束后广场出现无限清障对象，继续耗体并主要掉券；不因此假定所有清图活动有无限关卡 |

## 奖励与到期

本例区分地图宝箱、剧情大奖、任务手册、扭蛋结果、收藏奖励和兑换所得。达到条件、展示表现、玩家点击领取、入账户或主盘待领奖区分别说明。原稿部分领奖时机冲突，使用前见[待统一项](reference-conflicts.md)。

原稿结束规则值得单独描述，不能只复制“到期清空”：

1. 到达截止时间后，停止自然恢复及外部来源投放。
2. 玩家仍在活动内时，可使用已有活动资源，活动内产出仍可在本次会话使用。地图传送、手册与扭蛋弹窗属于活动内。
3. 返回主游戏、关闭活动或到期后重登等情况结束本次会话，清空剩余专属资源，不继承下期。
4. 活动外直接结束；未提交订单移除活动体力奖励，保留原订单需求及主线奖励。
5. 已达成未领取的任务和收藏奖励按补领规则处理，其中活动体力等专属数值不再发放。尚未领取的地图金币箱等奖励不按任务奖励补发。

上述仅适用于本例已经写出的结算方案；未领地图宝箱、未达成奖励、已达成未领任务要分清，不扩展补偿范围。

## 配置依据

原稿已有：障碍物掉落总表、剧情节点内容、ManualTask、ManualTarget、GachaMain、GachaToy、GachaQualityConvert、收藏组、GachaShop、分R订单系数。可按当前模块保留中文表头及语义，字段名仅作原稿参照。

原稿订单公式是“订单代币＝订单经验×分R配置系数”，此处代币在本活动中为活动体力。不能改成订单金币乘系数；没有写出的取整规则要标缺口。

障碍分段、掉落、手册关联等字段不能只写“字符串”。说明分别表示什么、何时读取、如何对应；`_`、`|`等只是原稿示例编码，研发可以调整。

原稿还写了礼包与数据来源等内容，整理该稿时保留本次要求范围内的内容，不因“默认至功能开关”而删除。新活动没有写商业化时不要复制过去。
