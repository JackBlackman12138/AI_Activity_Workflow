## 功能与验收
### R01 活动仅覆盖本期七天。达到7级、完成第6波订单且时间、资格、互斥关系、资源状态和开关允许时显示活动入口。首次进入展示一次开启封面；同一期仅初始化一次，保存分层、序列和读取位置。软关不影响已开启的本期；硬关时，活动内玩家可停留至主动离开。
- 来源：8.1、10.1、14
- 验收：用固定可达的Debug入口分别调整等级、订单波次、资格、时间和开关，观察入口出现或消失及不可用原因；进入、关闭、重进后，封面不重复且进度不重置。
- 配置：ActivityConfig、PlayerLayers、UiCopy
- 静态依据：state.js: `if (!draft.initialized) { ... draft.initialized = true; }`；入口按资格、时间和开关判定。

### R02 外部供券只通过玩家主动点击Debug操作模拟。分别提供「模拟订单结算成功／失败」和「模拟生成器有效产出命中／未命中／产出失败」；显示模拟来源、配置数量和操作结果。成功事件按配置发券并以事件ID去重；失败、未命中、过期或不合资格不发券。不制作订单、棋盘、生成器或其产出循环。
- 来源：8.2、10.1、12、13.2—13.3
- 验收：点击各Debug操作，核对券余额与事件记录；以同一事件ID重放成功事件不重复发券；正式截止后点击成功模拟也不发券，并明确显示拒绝原因。
- 配置：ActivityConfig、SupplyRules、UiCopy
- 静态依据：if (recorded(draft.processedEventIds, eventId))

### R03 主界面提供倒计时、券余额、累计与可用积分、五个阶段节点、扭蛋机、常驻Info、四档倍率、抽取、收藏、商店、说明及关闭入口。一次抽取扣除N×倍率张券，依次读取相同数量的序列项；跨房间继续读取，末房间按配置循环。余额不足保留倍率，失败不扣券、不推进序列。
- 来源：8.3—8.4、13.4—13.5
- 验收：分别选择×1、×3、×5、×10抽取，核对消耗、结果数和房间游标；在券不足时点击，看到策划指定提示且游标不变；连续点击仅产生一个已确认批次。
- 配置：ActivityConfig、DrawTiers、GachaSequence、PlayerLayers、UiCopy
- 静态依据：working.tickets -= tier.ticketCost

### R04 按结果顺序处理25件玩具：首次点亮收藏，同批后续相同ToyId按重复处理；五种品质重复分别增加1、2、3、5、10点，同时增加累计及可用积分。直接主游戏奖励记录模拟到账；棋盘承接类奖励仅记录模拟待领奖清单，不创建主棋盘。抽取结果之后依门槛处理自动阶段奖励，最后处理自动全收藏大奖。
- 来源：8.4、8.6—8.8
- 验收：抽到同批重复玩具时核对首次／重复状态及积分；跨越多个阶段节点时按升序出现领奖反馈；查看奖励账本，确认外发奖励有来源、数量和承接方式，重进不重复到账。
- 配置：GachaToy、QualityConvert、RewardCatalog、ProgressNodes、GachaSequence
- 静态依据：alreadyOwned ? convert.pointsPerDuplicate : 0

### R05 Info展示当前分层及序列统计范围的固定序列「投放占比」，不称为下一抽独立概率。逐件列出25件玩具，并按奖励及数量组合列出其他结果；显示品质重复积分、倍率含义和统计口径。展示值从实际生效序列计算，不维护可能失配的第二套数值。
- 来源：8.5、13.11
- 验收：首次抽取前打开Info，能滚动查看25件玩具和全部非玩具组合；逐项计数与当前序列配置一致、占比合计100%；切换Debug分层后重新进入，看到对应口径。
- 配置：GachaSequence、GachaToy、QualityConvert、RewardCatalog、PlayerLayers、UiCopy
- 静态依据：views.js 的 Info 仅提供 `FULL` 和 `LOOP` 范围；当前处于中间奖励房间时没有该房间的投放占比入口。

### R06 收藏页显示五条各含5件玩具的品质收藏线及25件总进度；未获得为锁定轮廓，新获得显示NEW。各品质满5件后分别手动点击奖励并经领奖弹板确认；全收藏大奖自动发放，不依赖品质奖励领取状态。
- 来源：8.6、8.10
- 验收：逐步点亮玩具，确认组进度及NEW状态；在5/5时进入收藏页手动领取，重复点击不重复到账；达到25/25后查看自动大奖及商店解锁。
- 配置：GachaToy、ProgressNodes、RewardCatalog、UiCopy
- 静态依据：MANUAL

### R07 五个累计积分阶段节点达标自动领奖；兑换只扣可用积分，不降低累计积分。商店与收藏入口并列，未全收藏可查看但不能兑换；解锁后按商品价格、次数和确认弹窗兑换，全收藏后仍能继续抽取。
- 来源：8.7—8.9
- 验收：全收藏前尝试兑换看到锁定原因；解锁后取消确认不扣分，确认后仅可用积分下降、次数增加且奖励到账；积分不足和售罄分别显示正确状态。
- 配置：ProgressNodes、GachaShop、RewardCatalog、UiCopy
- 静态依据：draft.availablePoints -= status.price

### R08 提供一次性开启封面、可关闭的新手引导、规则说明和商店解锁提示。引导解释Debug模拟的订单／生成器供券来源，但不要求游玩主线；引导中断不回滚已完成操作。

- 配置：ActivityConfig、UiCopy
- 静态依据：coverSeen

### R09 正式截止立即停止Debug外部供券。到期时仍在活动内可继续消耗已有券和积分，二级页返回不算离开；主动离开或模拟重登后进入一次性结束结算。已达成未到账奖励补发，未领取的已达成品质奖励进入补发列表；结束弹窗先于补发弹窗。本期剩余券及积分清零，外发奖励账本保留。时间未确认时不执行不可逆操作或清理。
- 来源：9.2、10、12、14
- 验收：在活动内将Debug时间调至截止后，验证抽取、领奖、兑换可继续而供券停止；关闭扭蛋机后看到结束及补发，重进不可继续；模拟时间不可确认时不能抽取、兑换或结算。
- 配置：ActivityConfig、ProgressNodes、UiCopy
- 静态依据：settlement.js: `expired && inside` 允许继续会话；`beginSettlement` 先排结束弹窗，`finalizeSettlement` 清理本期资产。
