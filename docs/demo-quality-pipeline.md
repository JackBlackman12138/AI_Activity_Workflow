# 完整 Demo 生成、验证与交付

## 用户流程

保持五阶段线性流程。根据已确认策划与配置生成完整工程，不增加新的用户审核表单。没有配置时生成默认演示值；已有数值优先。需求清单格式自动整理，不以清单缺省字段阻断业务实现。

生成流程为：整理需求与配置 → 创建多文件工程 → Node.js 编译 → 浏览器自动试玩 → 对照策划和实际截图核对 → 自动修复并重测 → 一起保存工程、预览、配置和验证记录。

发现问题时由平台修改，每次任务最多四轮自动修复；仍有问题时保留候选工程，不覆盖已保存 Demo，也不标记可交付。点击“继续自动修复”可基于相同输入下的候选工程继续。旧版 Demo 提供“完善并验证当前 Demo”，无需用户逐条看懂技术问题。诊断信息默认折叠。

对话修改复用原需求、完整工程与测试，只允许按文件中的唯一片段修改及新增文件。旧文件不能被整体覆盖，已有测试不能删除或降低断言。修改版重新编译、试玩与核对，通过后才替换当前版本。这减少回归风险，但不能宣称自动测试保证了所有玩法。

## 活动范围与 Debug

只实现本次活动。主线订单、棋盘、合成、生成器等外部依赖通过用户点击 Debug 模拟供给，不构建主线玩法；活动本身的地图或生成器仍按策划实现。Debug 发券、体力、材料及模拟来源参数读配置，不自动供给。活动消耗、抽奖、收藏、领奖和结算保持真实交互；发往主游戏的奖励以模拟到账清单承接。测试与审查遵守同一范围，不再要求主线棋盘容量或棋子数量。

生成范围带版本标记。旧候选不沿用旧需求与测试；旧已保存版本修改时按新范围重新整理，验证通过前不覆盖。新版活动工程的后续对话修改仍保留代码与回归测试。

## 实际工具与范围

- Node.js + esbuild：支持工程内 JS/TS/CSS/JSON/SVG 相对导入，编译成离线预览。源文件完整保留，不限制为几个代码文件（单次工程保护上限500文件、20MB）。入口为 index.html，脚本及样式可引用工程内文件。
- Playwright：使用本机 Edge、Chrome，或已安装的 Chromium。在与平台相同的隔离 iframe 和独立交付页面分别执行按钮、输入、选择、文本/数量/禁用状态断言与重载；另检查390×844、360×700视口。捕获真实脚本错误和未打包网络依赖，截图作为模型核对输入。
- 平台预览通过父页面存档桥提供隔离的 localStorage/sessionStorage 方法，不开放 iframe 同源权限。存档按活动、源码和配置版本隔离，刷新前确认落盘；“重新试玩”清除此版本进度。自动试玩与产品使用同一存档桥，独立交付页面使用浏览器原生存储。
- 测试场景由模型依据需求编写并存入工程，必须包含实际操作及结果断言。每场景独立上下文，最长一分钟；一组测试最长五分钟。这是本地测试的卡死保护，不是模型生成时限。
- 仅运行平台提供的编译器和浏览器工具，不执行模型生成的任意宿主 shell、npm 生命周期脚本或第三方插件。当前编译器不解析外部 npm 包；依赖应写为工程内模块。后续如需任意后端/包安装，应单独接入隔离执行环境。

API 主机必须安装可用浏览器。Windows 优先使用 Edge/Chrome；Linux 可运行 `npx playwright install --with-deps chromium`。启动生成前先检查浏览器，缺少运行环境时不消耗模型请求。现有 Dockerfile 仅提供静态前端，不包含新后台浏览器运行环境。

## 等待、暂停与草稿

模型默认连续30分钟无数据才停止，0表示无上限；持续输出或心跳会重置计时，没有模型总生成时长上限。网关自身仍可能提前关闭请求。可随时暂停，浏览器测试也接收中断信号。

输入、模型和 Skill 未变化时复用已完整保存的草稿；策划或配置变更后重新生成。暂停过程中尚未完整返回的模型输出无法续接。已完成任务的“重新生成”不复用旧候选。

## 通过的含义

新流程完成表示编译、已保存的浏览器场景和 AI 核对均通过，不保留已知阻断缺陷。测试不能穷举所有状态，最终体验、美术方向和正式数值仍需团队评审。演示假设在折叠详情和交付文档中保留。

具有自动审查记录的旧版或新版本，如果报告未通过、没有实际测试记录或源码/配置/策划版本不匹配，不能沿用历史结论确认交付。手动导入和本地示例不具有自动认证。

## ZIP 工程

- `project/`：所有原始源文件，开发修改以此为准。
- `project-files.json`、`project-tests.json`：工程文件清单与回归场景。
- `index.html`、`standalone.html`、`src/`：可运行入口与导出快照；离线配置已注入。
- `configuration.json`：全表配置编辑入口；`config/` 保存运行配置、每表JSON/CSV及多表XLSX。
- `docs/`：策划、整体逻辑、配置字段字典及验证记录。
- `tools/`、`package.json`：配置重建、源码编译、浏览器测试及本地预览脚本。
- `manifest.json`：文件校验信息。

直接打开 standalone.html 可试玩。修改原始工程前执行 `npm install`，然后 `npm run build` 重建，`npm test` 重跑浏览器测试，`npm start` 本地预览。新增文件加入 project-files.json。

修改 configuration.json 后运行 `npm run build:config` 更新运行配置，或 `npm run build` 同时更新独立试玩快照。CSV/XLSX 是导出快照，外部修改后需上传平台同步并重新导出，不会自动监控外部文件。
