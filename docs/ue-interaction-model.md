# UE 交互模型生成与交付（2026-09-30）

本阶段交付面向美术和 Unity 程序，是正式制作前确认玩法、状态、操作与反馈的 UE（用户体验）交互模型。源码为 Web 可执行参考，不是 Unity 工程，也不是 Unreal Engine 项目。

## 输入与默认数据

策划文档是主要输入，配置表为可选补充。生成器依据已确认策划整理业务默认值，已有用户数值优先。空的补充表可保留；未提供配置时平台提供交互流程表，业务默认值记录在默认配置或源码 defaults 模块及 assumptions 中。真实类型错误仍需修正，不能用默认值静默覆盖已填写的错误数据。

## 生成、运行与修复

1. 整理策划需求与默认数据，记录来源和待确认值。
2. 按依赖生成多文件工程，保存每一步，可恢复草稿。
3. 编译外部脚本入口及内联 module 入口为离线经典脚本，再注入平台运行时。
4. 在平台沙箱与离线页面运行浏览器测试，记录真实操作、错误与截图。
5. 针对实际问题局部修复。测试可新增前置操作和修正歧义定位器，普通定位修正保留原操作与期望值；若原生成测试与已确认策划规则冲突，必须写明对应规则与修订原因，保留需求覆盖与断言数量，并将前后场景保存为 docs/test-revision-*.json 供独立审查；click.count 表示逐次独立点击（1–200 次）。全部测试重新执行，失败版本不能自动视为交付通过。
6. 编译和实际运行检查通过即保存源码、默认配置和验证记录，允许用户确认并继续。AI 核对只提供参考意见，不触发自动修改、不要求清零，也不阻塞确认或导出。要调整玩法，由用户在对话框明确提出。恢复已有成果时，源码匹配则复用已有意见，避免重复审查。

不再通过源码文本中是否出现某张表的字面量来判断“SDK 已连接”，该检查会误伤动态读表和可选表。配置行为由运行测试与功能审查核对。

## 交付包

- project/：全部原始源文件。
- standalone.html：可离线试玩的模型快照。
- docs/features.md：功能需求、源码位置、测试操作、结果及配置关联。
- docs/unity-handoff.md：Unity 规则/状态/存档/服务迁移契约，美术页面状态与资源位置，以及待确认项。
- docs/requirements.json：机器可读需求、默认配置与假设。
- docs/configuration.md、configuration.json、各表 XLSX/CSV：配套数据与字段说明。
- docs/quality.md、project-tests.json：审查记录、自动化场景与人工核对项。

## 本地启动

双击仓库根目录的“启动工作台.cmd”。启动器检查 API 和前端，使用各自正确的工作目录；已启动的服务会复用，端口被其他程序占用会提示而不会结束未知进程。后台日志保存在 data/logs/。本脚本不设置开机自启。首次缺少依赖或编译文件时，先按项目说明安装并构建。

## 图片驱动的场景与交互修改

在「与 AI 交流修改」输入文字要求，可 Ctrl+V 粘贴或上传 PNG/JPG/WebP 参考图、截图和草图，每次最多 4 张。发送前可预览、移除。大图会缩至最长边 2048 像素并按需压缩，每张提交图最大 2 MB；发送失败保留输入。需要选择支持图片输入的模型，本地示例模型不支持识图。图片随修改任务保存，暂停恢复不丢图，任务记录可回看要求与图片。

模型结合原工程、文字与参考图局部修改场景布局、控件层级和交互；未要求的玩法保留。完整原测试仍执行，编译或运行失败才自动修复，AI 参考意见不阻塞确认。

## 加速与质量边界

依赖已完成且互不依赖的文件最多三个一批生成，保留清单、接口、逐文件保存记录和恢复能力。平台预览与离线环境并行验证，场景使用独立浏览器上下文；不删除场景、减少断言或跳过存档与刷新检查。实际耗时仍取决于模型接口、工程规模和自动检查。
