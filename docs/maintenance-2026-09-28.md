# AI Activity Studio：流程梳理与本次维护

更新日期：2026-09-28。项目位置：`D:\AIActivityStudio`。

## 当前流程

原有主流程保持五个阶段：

**创建活动 → 活动原稿 → 规则流程图 → UE 设计 → 策划文档 → 交互 Demo**

| 环节 | 目前的作用与产物 |
|---|---|
| 活动项目 | 创建、编辑、搜索、删除活动；活动包含类型、说明和原稿 |
| 活动原稿 | 保存或上传文本原稿，作为后续输入 |
| 规则流程图 | 根据原稿生成 SVG；保留可编辑源，支持 SVG/PNG 上传下载 |
| UE 设计 | 根据前序内容生成界面结构图；支持编辑、AI 修改和图像预览 |
| 策划文档 | 生成完整文本策划，支持保存、上传、下载和 AI 修改 |
| 交互 Demo | 在受限手机 iframe 中预览 HTML，并可下载独立 HTML |
| 模型中心 | 配置公司的兼容网关、模型和密钥，选择默认模型并测试连接 |
| 高级配置 | 分阶段管理默认 Skill 与上传 ZIP；当前 ZIP 只存储、校验和下载，未参与模型执行 |

五阶段生成仍要求前序产物存在。可主动重新生成已完成阶段，运行中的同阶段任务仍禁止重复提交。修改前序产物不会自动重做所有下游产物，后续阶段需要由策划按实际影响重新生成。

## 新增独立配置流程

**配置表中心 → 选择活动 → 从策划文档生成 / 上传配置 → 检查字段与数值 → 校验并保存 → 同步 Demo → 试玩 → 游玩节奏看板**

1. 从当前保存的文本策划中生成配置草稿。真实模型按约定结构提取；演示模型只读取文档中的 Markdown 表格，不凭空编造活动数值。
2. 在线修改字段名称、显示名称、说明、类型、必填规则及单元格内容；支持增删字段和节点行。
3. 支持 UTF-8 CSV 和 JSON 上传下载。CSV 适合 Excel 编辑；JSON 同时保留字段定义。当前不支持 XLSX、多工作表和跨表引用。
4. 上传先进入草稿；校验通过才允许保存。校验覆盖重复字段、必填项、数据类型、节点顺序所需的非负数/正整数及并发版本冲突。
5. 每次保存产生递增版本；同步后 Demo 使用固定的已同步快照，未同步的编辑不会悄悄改变正在试玩的版本。
6. 新活动可以直接生成配置驱动的顺序节点 Demo。它用于验证节点、操作次数、消耗和奖励，并不等同于完整活动玩法。
7. 现有自定义 Demo 需要读取 `window.ActivityStudio.config` 才能响应配置。未接入时会明确提示到 Demo 阶段重新生成，并保留原 Demo。不能保证任意旧 HTML 都能自动绑定新字段。
8. 下载 Demo 时内嵌已同步配置，可离线试玩；离线文件不会向平台回传记录。

## 看板口径

### 配置预测

按表格行顺序展示游玩节点、单节点/累计时长、操作次数、消耗与奖励。通过字段映射指定含义，缺少映射显示“未配置”。预计时长以秒计；消耗与奖励是每个节点的总量，同一列必须使用同一单位。

### 实际试玩

平台内 Demo 记录匿名会话、节点进入/完成、整体完成事件；展示会话数、完成率、平均节点耗时、完成耗时、到达率和最近路径。按当前配置版本隔离统计。

会话数不是独立玩家人数。未完成可能表示仍在进行，不能直接当作流失。耗时包含页面停留。当前每活动最多保留 20000 条本地事件，达到上限会提示，不能把这套本地记录直接当成线上玩家分析系统。

## 本次发现并修复的问题

| 问题 | 本次处理 |
|---|---|
| 地址固定追加 `/chat/completions`，完整接口地址容易重复 | 支持完整 URL 开关；已有标准路径时不重复追加，保留查询参数 |
| 多模型没有明确默认选择 | 支持默认模型；优先默认启用项，其次启用的真实网关，最后演示模型 |
| 后续生成没有充分使用前序产物 | 传递当前阶段之前的文本/可编辑源及 Demo 配置契约 |
| “重新生成”按钮与后端完成任务防重规则冲突 | 明确区分主动重新生成与普通重复提交 |
| 网关错误可能原样返回敏感响应 | 不再把网关错误正文写入前端/任务记录，统一返回状态和排查提示；请求增加超时 |
| 编辑活动原稿与 source 产物不同步 | 更新原稿同时更新 source；清空原稿移除对应产物 |
| 启动目录影响数据路径 | 显式 DATA_FILE 优先；根目录没有业务数据时继续兼容原 packages/api/data 文件 |
| 重启遗留 queued/running 任务永远不再执行 | 启动恢复为 paused 并写审计，用户可继续，不自动产生模型调用 |
| 页面固定显示服务已连接 | 根据初次加载结果显示连接状态 |

## 模型接入方式

模型中心新增/编辑流程包含：OpenAI Chat Completions 格式、请求地址、完整 URL 开关、模型 ID、显示名称、API 密钥、默认模型和启停。

基础地址示例：`https://gateway.example.com/v1`；完整地址示例：`https://gateway.example.com/custom/chat?version=1`。密钥加密保存在服务端，编辑时留空保留原密钥。点击连通测试会发送真实请求并消耗少量 Token。

接口结构参考 [OpenAI Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat)。本次仅使用模拟网关验证协议、路径、密钥保护和错误处理，**没有向公司网关发出真实请求**。公司若使用额外鉴权头、非 Bearer 鉴权、不同返回结构或独立 Azure 协议，还需要按实际网关文档适配。

## 仍需后续完善的部分

- 当前是固定本地用户和 JSON 存储；正式团队使用前需要用户权限、共享数据库、可靠任务队列和正式密钥管理。
- 现有 worker、数据库包还没有替换当前 API 内执行器与本地存储。
- 非 SVG 的视觉内容仍有简化渲染逻辑，复杂流程/UE 的保真需要后续单独优化。
- 当前配置基于单表、顺序节点；礼包表、掉落表、关卡表等多表联动，以及分支、并行、随机性和资源回复尚未建模。
- 文档提取目前面向文本策划；未新增 Word/PDF 解析。
- 真实网关返回的 Demo 是否完整遵循配置和事件契约，仍需用公司模型做一次真实生成验收。

## 启动与维护

在项目目录分别运行 `npm run api` 和 `npm run dev`。网页默认 5173，API 默认 3001。修改后端后需要重启 API；网页开发服务支持热更新。`npm run dev` 只启动网页，不会同时启动 API。

已有业务数据保留在 `D:\AIActivityStudio\packages\api\data\runtime.json`。显式 `DATA_FILE` 可覆盖路径。不要随意更换加密密钥，否则已有 API Key 无法解密。旧版演示密钥管理仍不是正式生产密钥方案。

主要新增文件：`packages/api/src/gateway.ts`、`packages/api/src/configuration.ts`、`packages/shared/src/demo.ts`、`apps/web/src/data-center.tsx`。相关接口、类型、执行器、主页面、样式及回归测试均已更新。
